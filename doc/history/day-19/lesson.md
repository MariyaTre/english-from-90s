## Полезный результат и структура

Первая функция — словарь с двумя пользовательскими полями: английское слово и русский перевод. Служебный `id` различает записи независимо от их текста. Предварительные имена полей — `english` и `russian`, таблицы — `words`.

Путь запроса: HTTP-клиент → `WordController` → `WordService` → `WordRepository` → PostgreSQL. Ответ возвращается обратным путём.

- Контроллер принимает запрос и формирует HTTP-ответ.
- Сервис выполняет действие сохранения или получения; правила данных добавляются по мере необходимости.
- Репозиторий отвечает за доступ к сохранённым словам через Spring Data JPA.
- Entity `Word` описывает соответствие Java-объекта записи в таблице.

Размещать предметные классы в подпакете `com.mashaikod.englishfrom90sback.words`, каждый публичный класс — в своём одноимённом файле. Не добавлять действия с данными в основной класс запуска и не создавать пустые интерфейсы/слои вне этих конкретных ответственностей.

2. Определить единственный способ создания таблицы до первого сохранения. Liquibase с SQL предложен Машей как возможный вариант, пока не обязательное решение. Если выбран, разобрать одну миграцию создания `words` и её однократное применение; не смешивать её с автоматическим изменением схемы Hibernate. 3. Создать минимальные Entity и репозиторий, объяснив связь объекта, `id` и строки таблицы.
4. Добавить сервис сохранения и чтения, контроллер с `POST /words` и `GET /words`. По месту использования объяснить JSON, передачу значений и HTTP-ответы. Требования к пустому вводу определить до приёмки сохранения.
5. Отправить запросы из доступного HTTP-клиента IDEA или терминала, посмотреть реальную запись через Database в IDEA. Тело запроса, выполнение и перезапуск делает Маша.
6. Самостоятельный перенос: сохранить другое слово без переписывания сервера, проверить обе записи, объяснить их идентификаторы.

## Проверка и качество

- Сохранение: ответ содержит сохранённое слово и выданный идентификатор, запись видна через подключение IDEA.
- Чтение: `GET /words` возвращает сохранённые данные; пустая таблица обрабатывается предсказуемо.
- Сохранность: после перезапуска Java слово остаётся. Сам факт ответа в памяти недостаточен.
- Подходящий ошибочный случай: пустое слово или недоступная БД, без ложного сообщения об успехе; не разбирать все ошибки в одной порции.
- Понимание: Маша прослеживает одно значение через контроллер, сервис, репозиторий и таблицу, объясняет роль каждой части.
- Качество: понятные имена, поля и ответственность классов, соответствие таблице, обязательные замечания исправляет Маша с повторной проверкой.
