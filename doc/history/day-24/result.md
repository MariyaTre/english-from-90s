## Вводные ответы и адресное объяснение

Маша верно назвала Word типом и предсказала отсутствие сохранения без команды вызова. word назвала «названием типа», wordRepository — объектом (направление верное, уточняется поле со ссылкой на объект репозитория). Предложила save(dress, платье) и отсутствие результата из-за отсутствия запроса получить. Это выявляет конкретные смешения: имя параметра/тип, один объект/два значения его полей, возврат из метода/отдельное чтение данных.

Помощь: разбор своего фрагмента Word word и return wordRepository.save(word), сопоставление одного объекта с карточкой ткани, в которой несколько характеристик. Уточняется, что аналогия иллюстрирует группировку данных, а параметр Java хранит ссылку. save принимает один объект слова и при успехе возвращает сохранённую сущность, return передаёт результат вызывающему коду, отображения на экране это не означает. Контракт сверён с официальной документацией CrudRepository: https://docs.spring.io/spring-data/commons/docs/current/api/org/springframework/data/repository/CrudRepository.html .

Ближайшая проба без изменения приложения: мысленно заменить имя параметра word на newWord, сохранив тип Word; попросить написать соответствующий вызов save и назвать, изменился ли тип.
