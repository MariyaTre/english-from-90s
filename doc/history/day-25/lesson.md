## Первая проба — до объяснения

Начать можно прямо в чате. Ниже фрагмент, который предполагается внутри `main` обычной Java-программы. Это материал для чтения, а не готовое решение самостоятельной практики.

```java
int buttonCount = 8;
int reservedCount = buttonCount;
buttonCount = 5;
System.out.println(reservedCount);
```

`buttonCount` — количество пуговиц, `reservedCount` — отложенное количество. Пока не запускай фрагмент.

1. Напиши свой прогноз: какие значения будут у обеих переменных перед последней строкой и что появится в консоли. Коротко объясни, как ты это определила.
2. Измени фрагмент так, чтобы **после изменения `buttonCount`** переменная `reservedCount` получила на две пуговицы больше текущего значения `buttonCount`. Вывод должен читать `reservedCount`. Пришли свой вариант и прогноз для него; результат числом в строку вывода не подставляй.

Если запись незнакома, укажи конкретную строку: её разберём, угадывать синтаксис не нужно. Эта проба начинает R001, но не подтверждает самостоятельного построения программы и не проверяет весь механизм вызова или назначение `main`.

## Объяснение и практика после первой попытки

Ответ на первую пробу пока не раскрывается. По попытке выберем самую раннюю непонятную операцию: объявление, чтение, присваивание или выполнение по порядку. При пробеле прямо отложим следующий шаг и разберём этот механизм с нуля.

Объяснение строим так: правильный термин → знакомая ситуация с записью мерки или подсчётом материалов → соответствие имени и значения → небольшой пример на других данных → действие Маши. Бытовая запись служит аналогией; поведение переменных проверяем по правилам Java и выполнению кода. Каждую новую часть примера объясняем отдельно. Разобранный пример подбирается после диагностики и не содержит решения самостоятельной задачи.

После разбора Маша изменяет понятный фрагмент, затем пишет небольшой вариант по условию с пустого места. Следующую задачу выдаём после предыдущей попытки. Существенный перенос меняет работу с данными или порядок вычисления, а не только числа и имена. Готовое тело программы и построчный план самостоятельной части не выдаются.

Если значение путается с выводом, подключим `CS-MEMORY`: отдельно проследим текущее значение и уже напечатанное. Новые типы, параметры, `return` и область видимости не становятся обязательным списком этого дня.

## Опоры и снятие помощи

Сначала можно записывать состояния после строк. Затем — прогнозировать короткий фрагмент мысленно и проверять запуском. Прогноз сохраняется до наблюдения; объяснение после запуска не заменяет его.

При необходимости на программе Маши вводим точку останова и один шаг отладчика (`DEBUG-STEP`). Маша сначала предсказывает изменение, затем делает шаг и сравнивает значения. Остановку перед строкой отличаем от уже выполненной строки. Заход в свой метод добавим при практике вызовов. Умение пользоваться отладчиком учитываем отдельно от понимания Java.

Готовую схему до первой попытки не показываем. При необходимости подберём визуальную опору под фактическое затруднение по `doc/visuals/README.md`.

## Требования к своему коду

- Имена — понятные английские слова в `camelCase`; незнакомое слово сначала поясняем. Имя помогает отличить назначение двух значений.
- Достаточно одного класса и локальных переменных внутри `main`, с ровным форматированием. Дополнительные слои не нужны.
- Расчёт использует значения переменных; напечатанный вручную ответ не проверяет вычисление.
- Ошибки и обязательные замечания Маша исправляет сама, после чего код проверяется повторно.

## Как проверим и где остановимся

**Поведение:** Маша запускает свой вариант, показывает вывод и сравнивает с прогнозом. После выбора расчёта проверяем относящийся к нему случай с нулевым количеством. Без запуска поведение остаётся непроверенным.

**Понимание:** нужны собственное построение и отдельный перенос с существенным изменением условия либо исправлением ошибки; в обоих случаях — прогноз, выполнение и объяснение пути значений. Начальное изменение готового фрагмента само по себе этого не подтверждает. Помощь сохраняется в результате дня.

**Качество:** проверяем имена, размещение, форматирование и использование данных. Обязательные замечания закрываются после самостоятельного исправления и повторной проверки.

Достаточный результат одной порции — законченная попытка с понятным выводом о том, что получилось и что разбирать дальше. Если трудность остаётся, продолжаем основу или сохраняем частичный итог. Число упражнений заранее не фиксируем; две успешные попытки не отменяют противоречащих им наблюдений.
