# Как вести справочник

Инструкция преподавателю. Сами страницы в `reference/` написаны для Маши: объяснения и навигация, без журнала обучения и правил ведения файлов.

## Структура и поиск

- Вход для читателя — [reference/README.md](reference/README.md). Структура: раздел → при необходимости подраздел → отдельная тема. Пример: `reference/java/variables/assignment.md`.
- В каждой папке `README.md` — короткое оглавление ближайших разделов/тем, с понятными русскими названиями и подсказкой «когда открыть». Не дублировать всю иерархию в корневом оглавлении.
- Папки и файлы называть устойчивыми английскими словами в нижнем регистре, при необходимости через дефис. Не привязывать путь к номеру урока. Не добавлять уровень вложенности ради одной пустой категории; подраздел нужен для осмысленной группы тем.
- Искать сначала в подходящем оглавлении; при необходимости — точечный поиск по заголовкам/ключевым словам. Не читать весь справочник ради одного ответа и не заводить второй полный каталог в JSON, реестре или отдельной таблице.
- Каждая тема содержит ссылки на оглавление своего раздела и родительские разделы. Связанные темы и подходящие готовые HTML-схемы связывать относительными ссылками; не копировать содержимое в несколько мест.

## Когда добавлять и разделять

После разбора понятия во время занятия или передачи удачного объяснения куратором найти существующую тему. Если это уточнение того же вопроса — поправить её. Если вопрос самостоятельный — создать отдельный файл по [шаблону](templates/reference-topic.md), добавить ссылку только в ближайшее оглавление. Новый раздел добавить в родительское оглавление. Не создавать заранее пустые папки, заглушки и полный курс.

Одна страница отвечает на один основной вопрос. Если на ней появляются несколько самостоятельных вопросов с собственными примерами, разделить их и связать ссылками. Большой материал сначала разбить по смыслу; не превращать страницу в новый бесконечный файл. Уже прочитанные страницы не переносить без необходимости; при переносе обновить ссылки и сохранить короткий переход со старого адреса, если он использовался в истории или переписке.

## Содержание для читателя

Короткое правило → небольшой пример → разбор и результат → существенная граница/типичная путаница. Использовать только нужные секции шаблона. Пример может быть сторонним или проверенным фрагментом кода Маши; не выдавать его за её работу без основания. Для фрагмента пояснить, где он находится, не называть его полной запускаемой программой. Новые учебные исходники и решения её заданий агент не создаёт.

Никаких «муж сообщил», дат наблюдений, оценок способностей/самостоятельности, планов проверок, инструкций агенту и ссылок на диагностические журналы. Источник объяснения и факт использования записываются в результате дня или наблюдении; оценка — в реестре. Наличие статьи не означает, что Маша её прочитала или освоила тему.

Справочник — разрешённая опора для Маши. Агент даёт ссылку на конкретную тему, а при непонимании объясняет в диалоге; чтение справки не является обязательным допуском к помощи. Обычную Markdown-страницу достаточно проверить чтением и проверить её ссылки. Не добавлять браузерный прогон ради текста; HTML проверяется по своим правилам и переиспользуется.

`doc/cheatsheet.md` остаётся коротким переходом для старых ссылок. Новый материал хранить только в `doc/reference/`.
