# Учебные схемы

Агент переиспользует готовые страницы и при необходимости создаёт небольшие автономные HTML-страницы, когда конкретный механизм удобнее увидеть: передача значений, область видимости, последовательность вызовов, изменение состояния, путь запроса. Это разрешённые куратором учебные иллюстрации; исходники приложения и упражнения Маши агент не пишет. Создание схемы не создаёт урок и не подтверждает понимание.

## Где хранить и как показывать

- [template.html](template.html) — готовый автономный шаблон версии 1 с демонстрационным содержимым и инструкциями для автора в комментариях. Его можно открыть двойным щелчком, без сборки, сервера и интернета.
- `topics/<topic>/v1.html` — конкретная тема, например [передача значений в метод](topics/java-method-values/v1.html). Это демонстрация подхода, ещё не пройденное Машей упражнение.
- В таблице ниже держать каталог существующих тем; в `history/day-N/result.md` ссылаться на фактически показанную версию и записывать реакцию/проверку понимания.
- После использования в занятии содержательную смену примера сохранять новой версией `v2.html`, чтобы старая ссылка из истории оставалась верной. Исправление фактической ошибки в старой схеме допустимо с заметной записью о коррекции в каталоге. Старые страницы не удалять.
- Показать страницу в доступном браузере/панели и дать Маше ссылку на реальный файл. Если панель показывает исходник, предложить открыть HTML браузером. Не утверждать, что Маша видела страницу, без подтверждения; не путать собственную проверку автора с демонстрацией ученику.

## Постоянный визуальный язык

Копировать шаблон, менять содержимое темы и логические состояния. Общие стили, размеры и обозначения сохранять; при осмысленной смене стиля повышать версию шаблона. В каждой странице оставлять версию в метаданных. Страницы самодостаточны: CSS и небольшой JS внутри, внешних шрифтов/библиотек, сетевых запросов, аналитики и установки зависимостей нет. Не делать зависимость старых схем от меняющегося общего скрипта.

| Элемент | Постоянное значение |
|---|---|
| Нейтральная панель кода с номерами строк | Читаемый код стороннего минимального примера |
| Синяя подсветка и подпись шага | Разбираемое действие; явно назвать, оно уже выполнено или предстоит |
| Карточка с заголовком области | Значения, доступные в указанном контексте, а не физическая схема RAM |
| Строка «тип · имя · значение» | Различие типа, имени и текущего значения |
| Подписанная стрелка | Передача конкретного значения/результата, направление обязательно |
| Зелёная отметка «результат» | Возвращённое значение или итог операции, не автоматическая печать |
| Отдельная панель «Консоль» | Только явно выведенный текст |
| Пояснение границ модели | Что рисунок упрощает и какие выводы из него делать нельзя |

Не кодировать смысл только цветом: названия областей, текст, значения и направления должны быть понятны без него. Не изображать локальное имя глобальной ячейкой и не смешивать область видимости со временем освобождения памяти. Для ссылочных значений Java отдельно показать копирование значения ссылки, если эта тема уже введена; пример с `int` не обобщать на копирование объектов.

## Как строить полезную схему

1. При первом введении порядка выполнения, памяти/консоли, копирования/восстановления значений, области видимости, вызова и возврата обязателен наглядный переход по [порядку объяснения](../explanation-first.md). Сначала выбрать подходящую готовую страницу. Если её нет/не открыть, дать короткую таблицу или простую схему в чате; объяснение и практика не ждут новой HTML-страницы. Новый HTML создавать при явной пользе для текущего затруднения или по запросу, не для каждой вариации задания. Для остальных тем выбирать по необходимости. Выбрать один вопрос и минимальный знакомый пример на других данных, без полного решения задания. Лишние понятия, слои и декоративные блоки убрать. Схема не нужна для каждого ответа.
2. При новой теме сначала самому объяснить хотя бы один переход, сопоставив код, значения и наблюдение; показать схему до самостоятельного задания. Прогноз до напоминания подходит только для повторения уже объяснённого и отработанного. При «не помню» или «не разбирали» вернуть объяснение.
3. Для динамики достаточно ручных «Назад»/«Дальше», без автоматического проигрывания. Для статической темы убрать шаговые кнопки и скрипт; сохранить тот же стиль карточек, подписей и таблиц.
4. Подписать момент состояния: до/после действия. Логические шаги объяснения могут отличаться от остановок реального отладчика — обозначить это явно. Не выдавать JS-анимацию за запуск Java.
5. В результате занятия и карте введения различать: схема подготовлена, ссылка отправлена, открытие подтверждено, переход разобран, действие Маши проверено. Собственный просмотр агента не является показом Маше. После просмотра попросить Машу проследить или изменить уже свой код. Факт открытия страницы и правильный пересказ схемы не повышает навык автоматически.

## Проверка перед показом

Браузерная авторская проверка нужна для новой страницы и после изменений, способных повлиять на смысл, состояния или отображение. Проверенную неизменённую версию повторно не открывать инструментами, не снимать новые скриншоты и не прогонять сценарии перед уроком. Показ ссылки Маше и авторская проверка — разные действия. Для новой/существенно изменённой страницы агент открывает итог браузером, просматривает снимок и исправляет проблемы. Проверить узкий экран около 360 px и обычный около 1280 px: читаемость, отсутствие обрезанных подписей, наложений и горизонтального переполнения. Проверить начало, середину и конец пошаговой схемы, оба направления, доступность кнопок с клавиатуры, соответствие кода/значений/консоли и отсутствие ошибок JS. Проверить работу без сетевых ресурсов.

Если рендеринг недоступен, записать «визуально не проверено» и не выдавать чтение HTML за просмотр результата; перед показом ученику завершить визуальную проверку. Результат авторской проверки хранить рядом с темой в `verification.md`, перепроверять затронутые состояния после содержательных изменений; мелкая правка опечатки без изменения смысла/вёрстки не требует полного прогона. Скриншоты технической проверки не обязаны попадать в репозиторий; сохранять сами HTML и краткую запись о проверенных состояниях.

## Переиспользование без лишних затрат

При показе готовой страницы достаточно каталога, записи о проверке и уверенности, что используется та же версия. При сомнении прочитать изменение/сверить сохранённую контрольную сумму; не начинать автоматом полную проверку. Сами кнопки Маша может переключать в своём браузере; агенту не нужно дублировать каждый её клик скриншотом. Не требовать установки браузерной автоматизации ради урока.

Новую сложную иллюстрацию можно подготовить при работе куратора над материалами; это не фоновая работа и не обещание создать её позже без запроса. Во время урока доступна простая текстовая опора. Новую непроверенную HTML-страницу не выдавать за проверенную: до проверки использовать таблицу в чате. В результате фиксировать фактически показанный формат, а не отмечать HTML выполненным по замене.
