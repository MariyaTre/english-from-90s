# Учебные схемы

Агент создаёт здесь небольшие автономные HTML-страницы, когда конкретный механизм удобнее увидеть: передача значений, область видимости, последовательность вызовов, изменение состояния, путь запроса. Это разрешённые куратором учебные иллюстрации; исходники приложения и упражнения Маши агент не пишет. Создание схемы не создаёт урок и не подтверждает понимание.

## Где хранить и как показывать

- [template.html](template.html) — готовый автономный шаблон версии 1 с демонстрационным содержимым и инструкциями для автора в комментариях. Его можно открыть двойным щелчком, без сборки, сервера и интернета.
- `topics/<topic>/v1.html` — конкретная тема, например [передача значений в метод](topics/java-method-values/v1.html). Это демонстрация подхода, ещё не пройденное Машей упражнение.
- В таблице ниже держать каталог существующих тем; в `history/day-N/result.md` ссылаться на фактически показанную версию и записывать реакцию/проверку понимания.
- После использования в занятии содержательную смену примера сохранять новой версией `v2.html`, чтобы старая ссылка из истории оставалась верной. Исправление фактической ошибки в старой схеме допустимо с заметной записью о коррекции в каталоге. Старые страницы не удалять.
- Показать страницу в доступном браузере/панели и дать Маше ссылку на реальный файл. Если панель показывает исходник, предложить открыть HTML браузером. Не утверждать, что Маша видела страницу, без подтверждения; не путать собственную проверку автора с демонстрацией ученику.

|---|---|---|---|
| Передача простых значений в метод | [Открыть схему](topics/java-method-values/v1.html) | 1 | Демонстрационный образец: аргументы, параметры, возврат, присваивание и отдельный вывод; [авторская проверка](topics/java-method-values/verification.md) пройдена, в уроке ещё не использован |

## Постоянный визуальный язык

Копировать шаблон, менять содержимое темы и логические состояния. Общие стили, размеры и обозначения сохранять; при осмысленной смене стиля повышать версию шаблона. В каждой странице оставлять версию в метаданных. Страницы самодостаточны: CSS и небольшой JS внутри, внешних шрифтов/библиотек, сетевых запросов, аналитики и установки зависимостей нет. Не делать зависимость старых схем от меняющегося общего скрипта.

| Элемент | Постоянное значение |
|---|---|
| Нейтральная панель кода с номерами строк | Читаемый код стороннего минимального примера |
| Синяя подсветка и подпись шага | Разбираемое действие; явно назвать, оно уже выполнено или предстоит |
| Карточка с заголовком области | Значения, доступные в указанном контексте, а не физическая схема RAM |
| Строка «тип · имя · значение» | Различие типа, имени и текущего значения |
| Подписанная стрелка | Передача конкретного значения/результата, направление обязательно |
| Зелёная отметка «результат» | Возвращённое значение или итог операции, не автоматическая печать |
| Отдельная панель «Консоль» | Только явно выведенный текст |
| Пояснение границ модели | Что рисунок упрощает и какие выводы из него делать нельзя |

Не кодировать смысл только цветом: названия областей, текст, значения и направления должны быть понятны без него. Не изображать локальное имя глобальной ячейкой и не смешивать область видимости со временем освобождения памяти. Для ссылочных значений Java отдельно показать копирование значения ссылки, если эта тема уже введена; пример с `int` не обобщать на копирование объектов.

## Как строить полезную схему

1. Выбрать один вопрос и минимальный знакомый пример на других данных, без полного решения задания. Лишние понятия, слои и декоративные блоки убрать. Схема не нужна для каждого ответа.
2. Сначала дать прогноз без показа следующего состояния. В отсроченной проверке не показывать готовый ответ до попытки. Затем раскрыть шаг и сопоставить код, значения и наблюдение.
3. Для динамики достаточно ручных «Назад»/«Дальше», без автоматического проигрывания. Для статической темы убрать шаговые кнопки и скрипт; сохранить тот же стиль карточек, подписей и таблиц.
4. Подписать момент состояния: до/после действия. Логические шаги объяснения могут отличаться от остановок реального отладчика — обозначить это явно. Не выдавать JS-анимацию за запуск Java.
5. После просмотра попросить Машу проследить или изменить уже свой код. Факт открытия страницы и правильный пересказ схемы не повышает навык автоматически.

## Проверка перед показом

Агент сам открывает итоговую страницу браузером, просматривает снимок и исправляет проблемы. Проверить узкий экран около 360 px и обычный около 1280 px: читаемость, отсутствие обрезанных подписей, наложений и горизонтального переполнения. Проверить начало, середину и конец пошаговой схемы, оба направления, доступность кнопок с клавиатуры, соответствие кода/значений/консоли и отсутствие ошибок JS. Проверить работу без сетевых ресурсов.

Если рендеринг недоступен, записать «визуально не проверено» и не выдавать чтение HTML за просмотр результата; перед показом ученику завершить визуальную проверку. Результат авторской проверки хранить рядом с темой в `verification.md`, при изменении содержания перепроверять. Скриншоты технической проверки не обязаны попадать в репозиторий; сохранять сами HTML и краткую запись о проверенных состояниях.
