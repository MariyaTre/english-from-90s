# Учебный маршрут «Английский из 90-х»

## Цель и текущая точка

Маша пробует фронтенд, бэкенд и мобильную разработку на одном понятном приложении. Главный результат — способность объяснить происходящее, самостоятельно применить знакомый приём и найти причину простой ошибки. Объём написанного кода не является мерой знаний.

Сейчас существует фронтенд на React/Vite и каркас Java 25 / Spring Boot 4.1.1 / Maven в отдельном репозитории `D:\Projects\english-from-90s-back`. Подготовлена PostgreSQL через Compose, добавлены JDBC-зависимости и настройки; старт Java подтверждён выводом, готовность PostgreSQL проверена. По пожеланию Маши ближайшая практика — полезный серверный цикл сохранения и получения слова через контроллер, сервис, Spring Data JPA-репозиторий и Entity, с просмотром строки в таблице через IDEA. Связь с React следует после проверки этого цикла. Пользовательское добавление слов и соответствующие серверные классы пока не реализованы. Подробности — в [project.md](project.md).

Есть сообщённые куратором затруднения с назначением переменных, типами значений и выводом данных через `map`. Это приоритетные темы для проверки и практики, но не основание откладывать знакомство с сервером. Остальные встречавшиеся в коде темы также нельзя считать освоенными без проверки.

Точка продолжения и номера дней хранятся в [history/README.md](history/README.md). Конкретный следующий урок составляется только по запросу Маши, по [порядку обучения](learning-process.md).

## Принцип движения

Работа идёт короткими итерациями вокруг одной функции приложения. В пределах итерации чередуются интерфейс, сервер и данные. Не требуется закончить весь фронтенд перед бэкендом; не требуется проходить отдельный полный курс языка перед первым полезным действием.

Первый практический шаг с Java/Spring должен попасть в первое или одно из первых трёх следующих занятий, ориентир — дни 18–20. До него достаточно выяснить необходимые для этого шага понятия и состояние окружения. При технической задержке записывается конкретная причина и следующий шаг, а серверная цель остаётся ближайшей.

Этап не равен одному уроку. Большой шаг дробится так, чтобы Маша успевала предсказать результат, сделать свою попытку и объяснить механизм. Базовые навыки повторяются на всём маршруте; для продвижения нужна самостоятельность в необходимых текущему шагу основах, а не отметка «освоено» у всего реестра.

Качество кода осваивается с первых занятий по [соглашениям проекта](code-quality.md): понятные имена, самостоятельные компоненты, осмысленное размещение файлов и разделение ответственности. При появлении нового блока сначала объясняется его место в проекте; при работе со старым выделяется необходимая для задачи часть. Проверка каждого результата включает замечания, самостоятельные исправления Маши и повторную проверку. Это часть текущей практики, а не отдельный этап «навести порядок когда-нибудь потом»; общий рефакторинг не откладывает первое знакомство с сервером.

## А. Первое взаимодействие браузера и сервера

**Статус:** серверный HTTP-шаг совмещается с первым сохранением слова из этапа Б; получение данных фронтендом следует после проверки API.

**Результат итерации:** Маша запускает фронтенд и Java/Spring-сервер, браузер получает небольшой ответ сервера и отображает его; Маша может проследить путь запроса и ответа. Это может быть небольшой элемент существующего приложения, без готового редактора слов.

Направления занятий:

- На существующем интерфейсе выяснить назначение имени, значения и переменной; постепенно различить строку, число, логическое значение, объект и массив.
- Рано познакомиться с Java: значение, явно указанный тип, переменная, метод, входные данные и результат — в объёме первого серверного действия.
- Проверить запуск созданного минимального Spring Boot-проекта в отдельном серверном репозитории `D:\Projects\english-from-90s-back`. Понять, какой процесс запускается, какой адрес слушает и где виден ответ или ошибка. Версии и команды выбирать по окружению и актуальной документации.
- Разобрать небольшой HTTP-запрос и ответ, назначение адреса, порта и эндпойнта; получить простой ответ сервера отдельно от React.
- Получить этот ответ из фронтенда. Постепенно объяснить ожидание результата и отображение ошибки. Настройку взаимодействия разных адресов разбирать при фактической необходимости.
- Сопоставить значения, методы и данные в двух языках на знакомой задаче. Не переносить автоматически оценки навыков JavaScript на Java.

**Проверка понимания:** Маша показывает, где выполняется каждая часть, откуда пришло отображённое значение и что произойдёт при остановленном сервере. Меняет небольшой элемент самостоятельно и проверяет прогноз.

## Б. Добавление и сохранение одного слова

**Статус:** ближайшая практическая итерация. Сначала API и проверка сохранения через HTTP-клиент и Database в IDEA, затем форма React.

**Результат итерации:** пользователь вводит слово и перевод, сервер принимает их, запись сохраняется в базе и загружается снова после обновления страницы и перезапуска сервера.

Направления занятий:

- Осмыслить существующую строку таблицы: массив → один объект → свойство; отдельно функцию преобразования и результат `map`.
- Первую серверную запись ограничить английским словом, русским переводом и идентификатором. Пройти `POST /words` и `GET /words` через контроллер, сервис, репозиторий Spring Data JPA и Entity; классы вводить по одному с объяснением ответственности.
- Проверять реальную строку через Database в IDEA и её сохранность после перезапуска Java. Запросы имени базы и пользователя не являются отдельной учебной целью.
- До создания таблицы выбрать один способ управления схемой. Liquibase с SQL — предложенный вариант для обсуждения на этом шаге, не обязательство; при выборе начать с одной миграции и объяснить повторный запуск.
- Различить данные, JSX и результат отображения React. `map` создаёт новый массив результатов; при возврате JSX React использует эти описания для отображения элементов. Это не автоматическое превращение любого объекта в HTML.
- Разобрать событие, обработчик, состояние и ввод на маленьком фрагменте. После объяснения одного поля самостоятельно сделать аналогичное и проверить независимость значений.
- Собрать минимальное добавление записи и сразу перейти к серверному приёму этих данных, не достраивая до этого все операции редактора.
- Постепенно разобрать JSON, метод запроса, тело, статус ответа и проверку входных данных. Временное хранение сервером в памяти допустимо как объяснимый промежуточный шаг.
- Подключить PostgreSQL через Docker Compose. Различить сервер приложения, процесс базы, контейнер и постоянное хранилище. Объяснить необходимость сохранения данных вне памяти приложения.
- Научиться создавать и читать запись в базе, затем связать этот путь с таблицей. Сначала понять строку, столбец и идентификатор; детали библиотек изучать при использовании.
- Проверить пустой ввод, выбранное поведение повторяющихся слов, недоступность сервера, перезагрузку страницы и перезапуск сервера. Не показывать ложный успех при ошибке.

Compose располагается в `_local/docker/docker-compose.yaml` относительно серверного репозитория; остальные материалы для локальной разработки — в его `_local/`.

**Проверка понимания:** Маша прослеживает одно значение от поля до базы и обратно, различает состояние интерфейса, память сервера и постоянные данные. Самостоятельно повторяет понятую операцию в изменённой ситуации.

## В. Первая мобильная проба

**Статус:** после первого сохранения слова, до большого редактора папок.

**Результат итерации:** небольшой мобильный клиент получает слова из того же сервера и показывает их; при готовности — отправляет новое слово. Это самостоятельная проба мобильной разработки, а не только узкая версия сайта в браузере.

- Перед началом выбрать с Машей доступную платформу и инструменты с учётом компьютера, телефона или эмулятора. Не навязывать стек без этих данных.
- Разобрать устройство экрана, небольшое действие пользователя и вызов знакомого API.
- Понять, где находится сервер относительно устройства/эмулятора и почему адрес может отличаться от адреса в браузере компьютера.
- Повторить знакомые данные и сетевой путь, вводя только необходимые новые конструкции мобильного стека.
- Зафиксировать, что понравилось, что оказалось сложным и какое направление Маша хочет попробовать следующим. Это предпочтения, а не оценка способностей.

**Проверка понимания:** Маша объясняет, что общее у веб- и мобильного клиента, а что относится к конкретному экрану и среде выполнения.

## Г. Небольшие функции редактора через весь стек

**Статус:** последующее развитие; порядок внутри этапа выбирается по навыкам и пожеланиям.

Каждый пункт — отдельная небольшая итерация с интерфейсом, серверной обработкой, хранением и проверкой. Мобильный клиент дополняется выборочно для практики, без обязательного дублирования каждого веб-экрана.

- Собственные слова каждого документа: устойчивые идентификаторы, связь документа и слов, независимость данных двух документов.
- Редактирование выбранного слова, сохранение и отмена; проверка, что соседние строки не изменились.
- Удаление слова, пустая таблица, повторное добавление; порядок строк и его сохранение.
- Создание папок и документов на рабочем столе и внутри папок.
- Вложенность, переходы и возвращение к родительской папке.
- Переименование с сохранением содержимого и связей.
- Удаление папок и документов и согласованное поведение корзины.

Точные действия интерфейса и спорные правила определяются перед соответствующей итерацией, затем поддерживаются в `project.md`. Изменения структуры данных также объясняются и выполняются Машей.

## Д. Тренировка и игровой диктант

**Статус:** после минимально удобной работы со своими словами; не требует завершения всех улучшений рабочего стола.

- Определить разницу между «Играть» и «Тренировка», источник слов, порядок, допустимые ответы и завершение занятия.
- Сделать небольшой цикл: задание → ответ → проверка → следующий шаг → итог.
- Разобрать условия, сравнения и изменение состояния на проверке ответа; убедиться, что учебный режим не портит исходный словарь.
- Добавить выбранные реакции мамы/бабушки, рыбу за ошибку и петушка за верный ответ после понимания основной логики.
- При желании повторить часть тренировки в мобильном клиенте.

## Е. Первая законченная версия и выбор направления

**Статус:** состав версии определяется по реально выполненным итерациям и интересам Маши.

- Пройти путь от своего материала до занятия с ним, включая повторный запуск и доступные ошибки.
- Довести необходимые размеры, прокрутку, подписи и поведение окон.
- Подготовить понятные инструкции локального запуска в `doc/`, проверить сборку и согласованные проверки.
- Выбрать способ публикации и самостоятельно разместить нужные части приложения.
- После практической пробы трёх направлений обсудить, какое Маша хочет изучать глубже.

Регистрация, личные кабинеты, расширенная статистика, интервальные повторения, аудио, свободное перемещение окон и прочие расширения не являются обязательными условиями первой версии. Их включают по явному интересу и понятной учебной пользе.

## Как менять маршрут

Новые пожелания отражаются в действующих требованиях и соответствующем этапе. Отменённые требования убираются из плана; завершённые результаты занятий остаются в истории. Для продвижения проверяются конкретные результаты и навыки, а не количество прошедших дней. Фиксированного срока окончания и расписанного заранее набора уроков нет.
