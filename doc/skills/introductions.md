# Карта введения понятий и инструментов

Эта компактная карта отвечает «что уже объясняли и показывали». [Реестр](registry.md) отвечает «что Маша может сделать», [очередь](review-queue.md) — «когда вернуться». Объяснение, знакомство и самостоятельность различаются. Не переносить оценки между ними автоматически.

Перед новой задачей читать нужные строки. При отсутствии сведений не требовать выполнить действие: спросить о знакомстве и, при необходимости, ввести по [порядку объяснения](../explanation-first.md). После реального объяснения обновить ссылку, оба примера, наглядную опору и результат совместной пробы. Материал, подготовленный агентом, но не показанный Маше, отмечать именно так. Старые успешные действия не обнулять из-за неполноты записи.

| Понятие / действие | Что известно о введении и источник | Что требуется перед следующей задачей |
|---|---|---|
| Редактор Java, файл и запуск main в IDEA | [День 26](../history/day-26/result.md): проект и запуск с помощью подтверждены. Полнота объяснения устройства редактора/файла отдельно не записана | Кратко уточнить нужное действие в интерфейсе; не считать всё устройство компьютера знакомым по запуску |
| Консоль вывода и терминал команд | Логи запусков присылались в днях 26–27; самостоятельное различение панелей не проверено. [Куратор 14 октября](observations/2026-10-14.md#обратная-связь-о-методике) привёл консоль как пример опасного предположения о знакомстве | Спросить о знакомстве, при необходимости показать назначение, место и отличие от редактора/терминала; конкретного незнания сейчас не приписывать |
| Порядок действий в простом main | Есть верные прогнозы в [дне 26](../history/day-26/result.md); куратор 14 октября сообщил, что порядок выполнения стал понятен после его объяснения 13 октября | Сохранить успех; спокойно восстановить модель по схеме и коду, без внезапной проверки всей Java |
| Присваивание, чтение, копирование простого числа | В днях 26–27 есть объяснения, практика и успешные собственные действия; полный набор «код + бытовой пример + HTML» не подтверждён | По [уточнению мужа](observations/2026-10-14.md#уточнение-о-присваивании-ожиданиях-и-лимитах), помогло «взять правую часть от равно и засунуть её в левую»; дата объяснения не названа, новой самостоятельной пробы нет. Сохранить эту опору; новую роль присваивания вводить отдельно |
| Восстановление сохранённого значения | [День 27](../history/day-27/result.md): сначала перенос, затем прямой запрос объяснения и поддержанные исправления | При возвращении начать с понятного объяснения цели и границ на другом примере, показать схему; до этого R008/R009 не использовать как проверку без помощи |
| HTML-схемы | В каталоге есть образцы; по сообщению куратора 14 октября в заданиях не использовались. Подтверждения показа в прочитанных результатах дней 26–27 не найдено | Подготовленный файл не равен показанному. Открыть подходящий материал перед самостоятельной практикой и записать реакцию |
| Область видимости | По [очереди](review-queue.md), R007: отдельной практики ещё не было | Это новое: два примера, наглядный переход (готовая схема или таблица), совместная проба; не проверять до введения |
| Вызов, параметры, return | В прежних занятиях встречались объяснения и затруднения; полного самостоятельного применения нет | По одному механизму с полным введением; срок R003 не делает всю связку знакомой |
| Отладчик | DEBUG-STEP запланирован; введение и самостоятельные действия не подтверждены | Спросить о знакомстве, показать нужную кнопку и панель, совместно пройти один шаг; затем прогноз и действие Маши |

Карта создана 14 октября по доступным записям и сообщению куратора. Она не является новым опросом Маши или переоценкой всех её навыков.

14 октября после обратной связи подготовлена схема [«Строки, значения и консоль»](../visuals/topics/execution-values-console/v1.html) с жизненным примером и полным сторонним Java-примером. Авторская проверка не означает, что схема показана Маше. При возвращении использовать её до самостоятельной задачи и отдельно объяснить восстановление сохранённого значения.
