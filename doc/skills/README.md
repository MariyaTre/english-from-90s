# Учёт навыков

[registry.md](registry.md) хранит текущую картину обучения. Это навыки Маши, а не плагины или исполняемые skills Codex. Реестр помогает выбирать практику; не нужно проходить его целиком перед следующей функцией.

## Единица учёта

Навык — проверяемое действие: «получить свойство объекта», «написать метод и использовать его результат», «найти ответ запроса». Определение термина не является отдельным доказательством умения. Слишком широкую тему вроде «знает JavaScript» разбивать на конкретные действия. Добавлять новые навыки по мере вопросов и задач, избегать дублей; ID сохранять стабильным.

У записи есть ID, название, статус, наблюдаемый критерий, основание оценки и ближайшая проверка/повторение. Точные индексы и состояния проверок хранятся только в [review-queue.md](review-queue.md); в реестре указывать ссылку и ID, а не вести второе расписание. Основание содержит дату и источник либо ссылку на результат дня. При изменении оценки обновлять запись, не накапливать в ней стенограмму. Детали попыток остаются в истории.

## Знакомство не равно самостоятельности

[Карта введения](introductions.md) хранит, где показаны объяснение, рабочий код, бытовой пример, схема и совместная проба. Реестр навыков хранит самостоятельность. «Не проверен», «Нужна практика» и наличие кода не разрешают предположить, что все необходимые части объяснены. Перед заданием найти свидетельство введения конкретного механизма; если его нет, сначала спросить о знакомстве и объяснить. Вопрос «знаешь ли, где консоль?» не заменять требованием дать определение.

Ошибку на новой или неоднозначно поставленной задаче не использовать для понижения всей знакомой основы. Сохранить узкие успехи, отдельно обозначить новый приём и нехватку объяснения. При ответе «не помню/не проходили» переключиться на введение и отметить степень помощи, не настаивать на попытке без неё.

## Статусы

| Статус | Значение |
|---|---|
| Запланирован | Понятие понадобится на маршруте, но ещё не вводилось |
| Не проверен | Понятие встречается в коде или прошлых материалах; самостоятельность неизвестна |
| Нужна практика | Есть затруднение или пока получается только с существенной помощью; указать конкретное основание |
| Самостоятельно | Есть две разные успешные практические попытки без подсказанного решения: собственное построение и существенный перенос; выполнение и объяснение проверены |
| Освоено | Успешное самостоятельное применение повторилось в другом занятии, на другой ситуации, после перерыва между занятиями |
| Повторить | После прежней самостоятельности проявилось конкретное затруднение; указать какое |

Для «Самостоятельно» нужны собственный код по условию и ещё одна практическая попытка с существенным изменением условия или самостоятельным исправлением ошибки. В этих попытках Маша прослеживает выполнение и значения, прогнозирует результат до запуска, сама проверяет его и объясняет механизм без подсказанного решения. Попытки могут быть в одном занятии. Замена чисел, имён, устный выбор ответа или повторение только что разобранного исправления не являются достаточным переносом. Для действий с инструментами проверяется самостоятельное действие с ними, а не искусственное написание кода. Точное воспроизведение формулировок не требуется. Для «Освоено» дополнительно нужно самостоятельное применение в другом занятии после перерыва, с новым условием; сохранять ссылки на оба занятия.

Наличие работающей функции, копирование разобранного примера, слова «понятно», правильный ответ после подсказки и прохождение сборки сами по себе не повышают оценку до самостоятельности. Отсутствие вопроса также не доказывает понимания.

## Как учитывать вопросы

Вопрос «что такое массив?» — повод занести или найти соответствующий навык и проверить его на маленьком действии. Вначале записать именно факт вопроса и неизвестность понимания; после ответа и попытки уточнить статус. Вопрос о сложной детали уже знакомой темы не обнуляет весь навык.

Сообщение куратора о пробеле учитывать как основание для приоритетной практики, явно называя источник. Не превращать его в вымышленную ошибку или реплику Маши. Если факт лишь предполагается по коду, писать «нужно проверить», а не «не понимает».

При существенной помощи отмечать её в результате дня: без помощи, направление поиска, напоминание правила, разобранная аналогия, разобранный конкретный фрагмент. Если решение показано, предложить другой вариант и оценить уже его. Обращение к справке за забытым синтаксисом не равно получению готового решения; важно, что Маша выбрала и объяснила действие сама.

## Как выбирать и повторять

1. Взять основной навык для ближайшей небольшой функции из плана. Выяснить необходимые для него основы и проверить их в объёме текущего шага.
2. Добавить 1–2 совместимых навыка из недавних затруднений или запланированного повторения. Не тренировать весь реестр в одном уроке.
3. При блокирующем пробеле основа становится главной темой по [practice.md](../practice.md), зависимая задача приостанавливается. Допустимы отдельная Java-песочница и несколько занятий практики; раннее знакомство с сервером уже состоялось и не обязывает продолжать Spring сейчас.
4. После подтверждения самостоятельности создать проверку в очереди с точным индексом: обычно N+1…N+3, после успешного повторения N+5…N+7 от фактической попытки. Интервал выбирается по наблюдениям. Для текущего пробела назначать ближайший контроль практики, не считать его повторением освоенного. Индекс — номер занятия, не дата.
5. После долгого перерыва коротко проверить нужные сейчас навыки. Не понижать статус только из-за прошедшего времени: для «Повторить» требуется наблюдаемое затруднение.
6. Перед завершением общения согласовать очередь и результат: конкретное действие, точный индекс, ID, источник и состояние. На индексе N брать открытые записи с индексом ≤ N, максимум 1–2 совместимые проверки за порцию; остальные переносить явно по правилам очереди. Проведённую в том же дне проверку повторно не выдавать. До напоминания проводить только явно обозначенное повторение ранее объяснённого и опробованного действия; новое вводить по `../explanation-first.md`.

JavaScript, Java и мобильный язык могут использовать общие идеи, но самостоятельность в новом языке проверяется отдельно. Не создавать ложного прогресса автоматическим переносом оценок.

## Глубина оценки и профиль навыка

В широкой теме разделять конкретные механизмы. Для Java отдельно учитывать объявление/изменение значения, тип, область видимости, порядок выполнения, вызов, аргументы, возврат и вывод. JAVA-VALUE и JAVA-METHOD сохраняются как обзорные строки с прежними наблюдениями; самостоятельность их частей учитывается отдельно и автоматически не переносится на всю тему.

Для текущей блокирующей основы в результате дня вести профиль:

| Сторона понимания | Что фиксировать |
|---|---|
| Чтение | Какие строки и значения проследила, прогноз до запуска и основание |
| Построение | Что написала с пустого места по условию, какие решения выбрала сама |
| Выполнение | Кто запускал, что наблюдалось; консоль и значение различаются |
| Перенос | Чем изменён механизм, какая помощь была доступна |
| Исправление | Причина ошибки и собственная правка, результат проверки |
| Объяснение | Как связала вход, действия и результат на конкретном коде |

Не требовать заполнения всех клеток после каждого сообщения. «Не проверено», «с поддержкой», «без помощи» и ссылка на попытку полезнее общего «вроде поняла». Профиль накапливается по ходу практики; ни одна словесная сторона не заменяет самостоятельного построения.

Уровни помощи: без помощи; справка только по синтаксису; направление поиска; напоминание правила; аналогичный разобранный пример; разбор конкретного решения; диктовка/генерация тела. Помощь мужа учитывать наравне с помощью агента. После показанного решения самостоятельность проверять новым вариантом. Нормальные подсказки редактора не запрещать, но результат генерации не выдавать за самостоятельное построение.

Обязательно отделять **наблюдение** от **гипотезы**. Например, ошибка в числе аргументов может быть связана с выражениями, вызовом или невнимательностью; различить причины следующим действием. Сообщение куратора — основание организовать практику и поставить «Нужна практика» с указанием источника, но не запись о лично проверенном ответе Маши. Ранние успешные узкие пробы сохраняются; более поздний пробел меняет ближайшую работу, а не стирает историю.

В реестре указывать блокируемый шаг и наблюдаемое условие возвращения. В результате дня сохранять факты попыток; при паузе оставлять конкретное действие, не общий пункт «повторить Java». Подробность учёта нужна для выбора следующей практики, а не для увеличения числа вопросов Маше.

При сообщении «я муж» действовать по [контракту](../mentor-contract.md). Для отладки отдельно учитывать `DEBUG-STEP`, не смешивая владение кнопками и понимание исполнения. Соединение знакомых действий проверять отдельно, например по `JAVA-INTEGRATE`; успех каждой части не даёт автоматической оценки целого.
