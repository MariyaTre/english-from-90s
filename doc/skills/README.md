# Учёт навыков

[registry.md](registry.md) хранит текущую картину обучения. Это навыки Маши, а не плагины или исполняемые skills Codex. Реестр помогает выбирать практику; не нужно проходить его целиком перед следующей функцией.

## Единица учёта

Навык — проверяемое действие: «получить свойство объекта», «объяснить, что возвращает функция», «найти ответ запроса». Слишком широкую тему вроде «знает JavaScript» разбивать на конкретные действия. Добавлять новые навыки по мере вопросов и задач, избегать дублей; ID сохранять стабильным.

У записи есть ID, название, статус, наблюдаемый критерий, основание оценки и ближайшая проверка/повторение. Основание содержит дату и источник либо ссылку на результат дня. При изменении оценки обновлять запись, не накапливать в ней стенограмму. Детали попыток остаются в истории.

## Статусы

| Статус | Значение |
|---|---|
| Запланирован | Понятие понадобится на маршруте, но ещё не вводилось |
| Не проверен | Понятие встречается в коде или прошлых материалах; самостоятельность неизвестна |
| Нужна практика | Есть затруднение или пока получается только с существенной помощью; указать конкретное основание |
| Самостоятельно | Есть одна успешная собственная попытка с объяснением и небольшим переносом |
| Освоено | Успешное самостоятельное применение повторилось в другом занятии, на другой ситуации, после перерыва между занятиями |
| Повторить | После прежней самостоятельности проявилось конкретное затруднение; указать какое |

Для «Самостоятельно» нужно, чтобы Маша могла объяснить назначение приёма, предсказать его результат и применить при изменённых условиях без подсказывания самого решения. Точное воспроизведение формулировок не требуется. Для «Освоено» нужны ссылки минимум на две отдельные подтверждённые попытки в разных занятиях, включая более поздний перенос.

Наличие работающей функции, копирование разобранного примера, слова «понятно», правильный ответ после подсказки и прохождение сборки сами по себе не повышают оценку до самостоятельности. Отсутствие вопроса также не доказывает понимания.

## Как учитывать вопросы

Вопрос «что такое массив?» — повод занести или найти соответствующий навык и проверить его на маленьком действии. Вначале записать именно факт вопроса и неизвестность понимания; после ответа и попытки уточнить статус. Вопрос о сложной детали уже знакомой темы не обнуляет весь навык.

Сообщение куратора о пробеле учитывать как основание для приоритетной практики, явно называя источник. Не превращать его в вымышленную ошибку или реплику Маши. Если факт лишь предполагается по коду, писать «нужно проверить», а не «не понимает».

При существенной помощи отмечать её в результате дня: без помощи, направление поиска, напоминание правила, разобранная аналогия, разобранный конкретный фрагмент. Если решение показано, предложить другой вариант и оценить уже его. Обращение к справке за забытым синтаксисом не равно получению готового решения; важно, что Маша выбрала и объяснила действие сама.

## Как выбирать и повторять

1. Взять основной навык для ближайшей небольшой функции из плана. Выяснить необходимые для него основы и проверить их в объёме текущего шага.
2. Добавить 1–2 совместимых навыка из недавних затруднений или запланированного повторения. Не тренировать весь реестр в одном уроке.
3. Если нужна основа, разбить задачу и потренировать её на знакомых данных. Сохранить раннее знакомство с бэкендом: основы можно объяснять также на Java и простом ответе сервера.
4. После первой самостоятельной попытки назначить возвращение через 1–3 следующих занятия; после подтверждённого повторения — примерно через 5–7 занятий либо при ближайшем применении. Это ориентир, а не жёсткое расписание.
5. После долгого перерыва коротко проверить нужные сейчас навыки. Не понижать статус только из-за прошедшего времени: для «Повторить» требуется наблюдаемое затруднение.
6. Перед завершением общения сохранить следующую проверку: конкретное действие и номер/условие возвращения. При пропущенном сроке выбрать ближайшее подходящее занятие, не добавляя сразу все просроченные темы.

JavaScript, Java и мобильный язык могут использовать общие идеи, но самостоятельность в новом языке проверяется отдельно. Не создавать ложного прогресса автоматическим переносом оценок.
